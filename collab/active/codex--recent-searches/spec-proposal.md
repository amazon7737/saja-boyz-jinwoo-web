# 최근 검색 — 명세 초안

2026-10-10 · dev f5bc8cf 기준. 정확 테스트 5개와 함께 사용자 승인 전이다.

## 목표

기존 기사 키워드 검색에 Figma 최근 검색 목록을 연결한다. 브라우저에 실제 실행된 검색 기록을 저장하고, 다시 선택하면 동일한 기사 검색을 실행하며 개별 삭제할 수 있게 한다.

## 동작

- /search의 빈 검색 화면에 접근성 이름 '최근 검색'인 section을 추천 검색어 위에 배치한다. Figma 11:1797 및 11:1814의 12px muted heading, 14px 검색어, 시계 문자, 얇은 하단 경계, 8px 간격 및 오른쪽 삭제 표시를 기존 Tailwind 토큰으로 구현한다. 화면 표제는 '최근 검색', 비어 있으면 '최근 검색어가 없어요'. 샘플 검색어·iOS 상태바·기존 하단 메뉴의 미구현 아이콘을 새로 추가하지 않는다.
- localStorage의 hh:recent-searches:v1에 JSON 문자열 배열로 브라우저별 기록을 저장한다. 서버 저장·로그인 동기화 없음. 서버 렌더에서 저장소에 접근하지 않으며 hydration 불일치 없이 클라이언트에서 복원한다.
- 실제 검색 결과 경로의 정규화된 q를 기록한다. 앞뒤 공백 제거, 배열 q는 첫 값만 사용한다. 비어 있지 않은 URL 검색은 폼 제출·추천/최근 검색 선택·직접 URL 진입·실패/빈 결과를 포함한다. 입력만 하는 중이나 빈 값은 기록하지 않는다.
- 최신 검색이 앞에 온다. 정규화한 동일 문자열은 하나만 남기고 재검색하면 맨 앞으로 이동한다. 대소문자는 임의로 바꾸지 않는다. 최대 10개이며 초과 시 오래된 기록을 제거한다.
- 최근 검색 항목은 /search?q=encodeURIComponent(keyword) 링크다. 기존 Next Link 및 검색 대기 표시를 재사용하고 현재 기사 API 호출을 유지한다. 주소 검색·알림 구독처럼 표시하지 않는다.
- 개별 삭제는 type=button, 접근성 이름 '${keyword} 삭제'로 구현한다. 해당 항목만 제거해 화면과 저장소에 반영하며 검색 제출/페이지 이동/API 요청을 일으키지 않는다. 새로 방문해도 삭제는 유지한다. 입력·제목은 텍스트로 렌더하고 HTML로 실행하지 않는다. 긴 검색어도 삭제 버튼을 밀어내거나 가로 넘침을 만들지 않는다.
- 저장값은 문자열 배열인지 검증하고 잘못된 원소·빈 문자열은 무시하며 중복과 개수 제한을 적용한다. JSON 손상·배열 아닌 값은 빈 기록으로 처리한다. 저장소 접근·쓰기 예외는 기존 검색·추천·내비게이션·오류 경계를 깨뜨리지 않는다. 저장 불가 시 지속 저장을 보장하지 않는다.
- 검색 결과 화면에서는 최근 목록을 노출하지 않고 검색어 기록만 처리한다. 초기 GET form, URL/입력 동기화, 추천 검색어, 초기화·재시도·빈 결과·로딩 흐름과 지도/목록 등 다른 경로를 유지한다.

## 구조와 범위

src/features/search/ui/recent-searches/에 UI와 관련 테스트를 모으고 필요하면 최소 모델 모듈 하나를 둔다. CSS 파일·새 제품 의존성·전역 store·API 스키마 변경 없음. 기존 40개 테스트 본문·helpers·fixtures와 전체 테스트 명령을 유지한다. 전체 삭제·탭 간 즉시 동기화·주소 자동완성·지도 사건 기능·상세·제보는 제외한다.

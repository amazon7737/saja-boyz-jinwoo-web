# Figma 반영 확인 — 2026-10-04

## 결론

기존 목록 표시 컴포넌트는 Figma의 구조와 주요 치수를 반영했지만, 완전 일치는 아니다. 이번 기사 API 화면은 아직 구현 전이므로 디자인 반영 완료로 보고하지 않는다.

## 대조 자료

- Figma에서 새로 확인한 [목록 본문 11:2153](https://www.figma.com/design/TCSILMzViAVqeHRphoyHCH?node-id=11-2153)의 디자인 문맥·스크린샷.
- [전체 목록 11:2123](https://www.figma.com/design/TCSILMzViAVqeHRphoyHCH?node-id=11-2123)의 화면 치수.
- 앱 `71da47d`의 `src/features/incident-list/` 소스와 CSS. 기존 임시 프리뷰 복사본과 파일 해시 일치를 확인했다.
- `http://127.0.0.1:3001`의 임시 프리뷰에서 320px·393px 영역, 정상·사진 없음·빈 결과·로딩 상태를 확인했다. 새 기사 API 화면의 증거로 사용하지 않는다.

## 일치한 항목

| 항목 | 브라우저와 Figma 대조 |
| --- | --- |
| 목록 | 좌우 16px, 위아래 8px, 카드 간격 12px |
| 카드 | padding 12px, radius 14px, 흰 배경, border #e2e8f0 |
| 이미지 | Figma 이미지 5개 정상 로딩, 80×80px, radius 8px |
| 글자 기본값 | 제목 14px/800, 메타 11px, 요약 12px/16px |

320px·393px의 현재 샘플에서 가로 넘침은 없었다. 사진 없음은 80×80px 대체 표시와 링크를 유지했다. 빈 결과·로딩은 카드가 0개이며 로딩에는 `aria-busy=true`가 있었다. 단, 이 상태들의 별도 Figma 시안 일치는 확인하지 않았다.

## 확인된 차이

1. 배지 글자색은 원색 55%와 #0f172a를 섞어 Figma보다 어둡다. 정치 배경은 Figma #e0f2fe와 다르고, 국제의 배경·글자색도 다르다.
2. 실제 393px 컴포넌트 영역에서 카드는 361×125px, 오른쪽 내용 영역은 243px이다. Figma는 각각 361×120px, 245px이다. border의 내부 공간 차이와 실제 메타 줄 높이 15px(Figma 13px)가 영향을 준다.
3. 전역 CSS에 Pretendard·Inter 이름은 있으나 폰트를 로드하는 설정이 없어 실제 글꼴 일치를 보장하지 못한다.
4. 시안의 “종료”를 “종결”로 표시하는 것은 기존 승인 계약에 따른 의도된 차이다.

## 기사 API 연결 시 반영할 사항

- AppShell 자체가 좌우 16px을 가진다. 기존 목록의 좌우 16px까지 중첩하면 총 32px이 되므로, 새 라우트에서 최종 카드 여백은 16px 한 번만 적용한다.
- API가 제공하지 않는 분류·상태·위치·발생 시각을 없애고 기사 발행·원문·AI 이미지 문구를 넣는 차이는 제품 결정과 데이터 계약에 따른 것이다.
- 새 실제 기사 화면에서 긴 제목·이미지 실패·API 오류/빈 응답·로딩 전환·원문 이동·전체 shell·태블릿/데스크톱을 다시 검증해야 한다.
- 기존 배지 색상이나 공용 폰트·헤더·필터를 이번 API 연결 준비 과정에서 수정하지 않았다.

브라우저에는 외부 확장이 삽입한 `body.__text_mode_READY__`와 관련된 hydration 경고가 하나 있었다. 이를 앱 자체 결함으로 단정하지 않았다. 프리뷰 코드는 수정하지 않았고 브라우저 크기는 검증 후 복원했다.

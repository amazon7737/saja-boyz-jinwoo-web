# 기사 API를 연결한 사건 목록 — 명세 제안

상태: 사용자 검토용 초안. 기사 1개를 사건 1개로 본다는 제품 결정과 작업 진행 지시는 확인했다. 이 문서는 아직 사용자 소유 `spec.md`에 적용하지 않은 구체적인 후속 명세다.

## 결과와 범위

실제 `/incidents` 페이지가 뉴스 API의 기사를 목록 카드로 표시한다. 기존 `IncidentList`의 승인된 동작·테스트와 공용 `Incident` 타입을 보존하고, API에 맞는 기사 표시 계층을 별도로 둔다. 상세·제보 페이지와 솔피 담당의 공용 필터/UI는 수정하지 않는다.

첫 연결은 **최근 수집 이력 20행의 한 배치**를 조회한다. 같은 `article_id`는 처음 받은 행 하나만 표시하며, 서로 다른 ID는 제목이 같아도 별도 카드로 남긴다. API의 수집 순서를 유지한다. 중복이 있으면 카드 수는 20개보다 적을 수 있다. 검색·페이지 이동·전체 이력 탐색은 이번 단계에 넣지 않는다. API `total`은 수집 행 수이므로 전체 사건 수로 표시하지 않는다.

## 읽기 요청과 실패

- 서버 전용 환경변수 `NEWS_API_BASE_URL`로 지정한 HTTP(S) API에 `GET /news?offset=0&limit=20`을 보낸다. 브라우저가 직접 API를 호출하거나 수집 POST를 실행하지 않는다.
- 요청은 `cache: 'no-store'`이며 본문이 없다. 5초 제한으로 요청을 취소한다.
- 환경변수 미설정·잘못된 URL·HTTP(S) 외 URL·사용자정보가 들어 있는 URL이면 요청하지 않고 오류 화면을 표시한다.
- HTTP 실패, 네트워크 오류, 시간 초과, JSON 파싱 실패, 사용할 수 없는 응답 구조는 빈 목록과 구분한다. 목록 자리의 `role="alert"`에 “기사를 불러오지 못했어요”와 `/incidents`로 다시 조회하는 “다시 시도” 링크를 표시한다. 서버 오류 본문·내부 예외 문구는 화면에 노출하지 않는다.
- 성공 응답은 `{ total, items }` 구조와 기사 필드의 타입을 검사한다. ID가 64자리 소문자 hex가 아니거나 제목·요약·발행 시각이 문자열이 아닌 행이 있으면 전체 응답을 오류로 취급한다. 날짜·출처·이미지 주소의 의미상 오류는 아래 카드 대체 표시를 사용한다.

## 카드

- 제목과 요약은 HTML 태그를 제거하고 일반적인 HTML 엔티티(`amp`, `quot`, `apos`, `lt`, `gt`, `nbsp`, 10진·16진 문자 참조)를 텍스트로 변환한다. 유니코드 범위 밖이나 단독 서로게이트를 나타내는 숫자 참조는 원래 문자열을 유지해 카드 표시가 중단되지 않게 한다. 결과를 React 텍스트로 렌더하며 HTML로 주입하지 않는다.
- `pubDate`는 **기사 발행**이다. 유효한 날짜에는 실제 ISO 시각을 가진 `time`과 `YYYY-MM-DD HH:mm KST` 형식의 절대 시각을 표시한다. 유효하지 않으면 `time` 없이 “발행 시각 미확인”을 표시한다. 미래 발행 시각도 주어진 절대 시각으로 표시하며 현재 시각이나 발생 시각으로 대체하지 않는다.
- API에 없는 사건 분류·진행 상태·위치·좌표·타임라인·언론사 이름을 추측해 채우지 않는다. 카드에 그 필드를 표시하지 않는다.
- 안전한 절대 HTTP(S) `originallink`를 우선 사용하고, 유효하지 않으면 안전한 `link`를 사용한다. 사용자정보 포함 URL, 상대 URL, HTTP(S) 외 스킴은 링크로 만들지 않는다. 링크 문구는 “기사 원문”이다. 둘 다 사용할 수 없으면 카드 정보를 보존하고 “원문 링크 없음”을 표시한다.
- 아직 구현되지 않은 `/incidents/[id]`로 이동시키지 않는다.
- `image_status === 'ready'`이고 현재 기사 ID의 `/images/<article_id>.jpg` 경로일 때 API origin 기준 이미지와 “AI 생성 이미지” 문구를 표시한다. 크기는 80×80px이다. 나머지 상태, 없는 주소, 다른 출처 또는 다른 기사 ID의 주소는 “이미지 없음”으로 대체한다. 이미지 로딩 실패 시의 브라우저 결과도 완료 검증에서 확인한다.

## 상태와 화면

- 성공한 빈 응답은 `role="status"`에 “아직 수집된 기사가 없어요”를 표시한다. 미구현 검색·필터를 바꾸라는 안내는 하지 않는다.
- `/incidents/loading.tsx`는 기존 로딩 컴포넌트의 “사건을 불러오는 중”, `role="status"`, `aria-busy="true"`를 사용하며 API를 중복 요청하지 않는다.
- 목록 내부에 공용 헤더·탭·내비게이션을 중복 생성하지 않는다.
- 기존 Figma 목록 카드의 여백·타이포그래피·색상·80px 이미지 규칙을 참고한다. `AppShell`을 포함한 393px 화면에서 카드 바깥 좌우 여백은 16px 한 번만 적용한다. 원본에 있는 사건 메타데이터의 삭제와 발행·원문·AI 이미지 문구는 실제 API 계약 때문에 필요한 차이다. Figma와의 실제 일치 여부는 브라우저 대조 기록으로 별도로 보고한다. 기존 배지 색상·전역 폰트 수정은 별도 범위다.

## 보존 및 완료 검증

- 기존 13개 테스트, 보호된 지원 파일, 승인된 `IncidentList`의 인터페이스·테스트를 보존한다.
- 새 8개 라우트 테스트는 `failed-test.draft.md`의 정확한 헤더·본문을 승인한 뒤 순서대로 진행한다. 테스트에서 사용하는 네트워크 응답은 합성 데이터이며 운영 호출을 하지 않는다.
- 필요한 테스트 지원 변경은 `vitest.config.ts`에 실제 앱의 `@` 경로 해석을 추가하는 것 하나다. 전체 테스트 명령·기존 셸 스위트·실행 제한·의존성을 바꾸지 않는다.
- 승인에는 이 제안을 `spec.md`에 기록하는 권한, 정확한 테스트 계획을 `failed-test.md`에 기록하는 권한, 지원 설정 적용과 Sobaya 기준선 기록을 포함한다.
- 최종 완료는 전체 테스트·format·lint·typecheck·build, 실제 로컬 페이지의 운영 GET 결과·모바일/데스크톱·원문 링크·이미지·로딩/빈 결과/오류 확인, Sobaya 최종 gate와 HEAD에 묶인 독립 리뷰로 판단한다. 정적 렌더 테스트 통과를 실제 화면이나 디자인 일치의 증거로 사용하지 않는다.

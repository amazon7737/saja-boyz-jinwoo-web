# 코드 작성 컨벤션과 가독성 통일

사용자는 2026-10-11 코드 작성 컨벤션 정리와 dev 대상 PR 진행을 승인했다. 기능과 테스트 계약은 유지한다.

## 범위

- 제품 src의 TypeScript/TSX 파일에 외부 의존성 → 내부 alias → 상대 경로 import 구획, 마지막 import 뒤 공백, 최상위 타입·상수·함수·export 사이 공백을 적용한다. CSS 등 부작용 import의 실행 순서를 바꾸지 않는다.
- 함수 안에서 변수 선언 묶음과 처리 단계·반환·블록 사이 공백을 두어 검증 → 처리 → 반환을 읽기 쉽게 한다. 관련 변수마다 무조건 공백을 넣거나 JSX 요소마다 빈 줄을 강제하지 않는다.
- 기존 Next ESLint에 등록된 import 플러그인과 현재 ESLint의 내장 공백 규칙을 재사용한다. 신규 의존성·커스텀 플러그인을 추가하지 않는다. 규칙은 제품 소스에만 적용하고 기존 승인 테스트는 byte 단위로 보존한다.
- layout.tsx의 metadata를 읽기 좋은 블록으로 정리한다. AppShell의 긴 조건부 클래스와 헤더 노출 조건은 같은 파일의 의미 있는 변수로 표현한다. DOM·Tailwind 클래스·라우트·오류 경계·클라이언트/서버 경계·컴포넌트 책임은 유지한다.
- docs/code-conventions.md에 파일 배치·공백·Props와 이름·핸들러·JSX 구획·과한 분리 방지 기준과 실제 예시를 작성한다. 기존 architecture.md에서 연결한다. 동료가 같은 기준을 따르도록 저널 rule로 공유한다.
- 테스트·fixture·Test/Format/Lint 명령·package scripts·의존성·폴더 경로·페이지네이션·지도·제보 기능은 변경하지 않는다. 불필요한 리네임·새 컴포넌트·공용 추상화를 만들지 않는다.

## 검증

- Sobaya의 별도 승인된 구조 리팩터링 계약에 따라 기존 전체 61개 테스트를 변경 전후 실행한다. 새 행동이나 신규 RED 항목은 없으며 테스트를 억지로 추가하지 않는다.
- 최종 Sobaya gate와 별도 읽기 전용 Astra 리뷰, Format/Lint, TypeScript, 프로덕션 빌드를 통과해야 한다.
- 기존 모든 테스트/fixture가 기준 dev와 동일하고 package scripts와 의존성도 동일함을 검사한다. 대다수 제품 파일의 AST가 import 배치·공백 정리 전후 같음을 확인하고 AppShell의 조건 추출만 별도 검토한다.
- 기준 dev와 최종 src의 실제 Chrome 주요 라우트 화면을 같은 fixture·viewport로 비교해 DOM·화면·콘솔 오류가 유지되는지 확인한다.
- 문서·저널·검증 자료를 포함해 dev 대상 PR을 리뷰 가능한 상태로 올린다. PR 제목·본문은 코드 컨벤션 통일 목적과 변경/검증 근거로 작성한다. amazon7737 리뷰 요청. GitHub 코멘트·병합은 별도 승인 전 하지 않는다.

# 검색 결과 더 보기

2026-10-11 · 사용자 요청 “ㅇㅇ 진행해봐 전과정승인함 시작”의 범위.

기존 기사 키워드 검색에 누적 더 보기를 추가한다. 첫 20개는 서버에서 렌더하고 같은 검색어의 다음 페이지를 버튼으로 가져와 기존 결과 아래에 붙인다. 검색 URL·폼·추천·최근 검색·상세·원문 링크와 목록 화면을 유지한다.

## 동작

- API의 offset·limit=20·keyword를 그대로 사용한다. offset은 화면 카드 수가 아닌 성공 응답의 원본 items.length 누적값이다. article_id 중복은 페이지 안/페이지 사이에서 제거하며 첫 등장 순서를 보존한다. total은 중복 포함 원본 행 수이므로 기사 건수로 표시하지 않는다.
- 원본 누적 offset이 최신 응답 total에 도달하거나 다음 페이지가 비면 더 보기를 숨긴다. 짧은 페이지라도 total이 더 크면 계속 가능하다. 기존 최대 20개 안내를 실제 누적 동작에 맞게 바꾼다. 첫 빈 결과·최초 조회 오류는 기존 UI를 유지한다.
- 더 보기 로딩 중 중복 요청을 막고 접근성 상태를 표시한다. 추가 조회 실패는 기존 카드·URL을 유지하고 내부 서버 메시지를 노출하지 않는다. 다시 시도는 실패한 offset을 다시 조회한다.
- 검색어가 바뀌면 누적·offset·오류·로딩을 초기화하고 새 검색의 첫 페이지만 표시한다. 이전 검색의 늦은 응답은 새 결과를 바꾸지 않는다. 빈 검색/초기화는 API 요청 없이 추천·최근 검색을 보여 준다.
- 서버의 비공개 NEWS_API_BASE_URL을 브라우저에 넘기지 않는다. 더 보기 요청은 같은 앱의 server action 또는 같은 origin route로 중계한다. 서버 요청 경계에서 keyword 문자열과 trim 결과 비어 있지 않음, offset의 안전한 0 이상 정수 여부를 검사하며 사용자에게 임의 원격 URL을 받지 않는다. 5초 제한, no-store, 기존 응답 필드 검증을 유지한다.
- fetchArticleList의 기본 호출은 기존 offset=0·limit=20을 유지하며 offset 선택 인자와 total 반환을 추가할 수 있다. 공용 API helper는 목록에서도 재사용 가능하도록 기존 인터페이스를 보존한다.

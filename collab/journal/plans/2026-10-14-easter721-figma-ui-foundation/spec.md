# feat(ui): Figma 공통 디자인 기반과 화면별 레이아웃 재구축

## 목표

승인한 전체 디자인 재구축 계획의 첫 단계다. 공통 폰트·색·간격·SVG 로고·검색 헤더·하단 메뉴·필터 표면과 지도/검색/목록/상세/제보의 화면 틀을 Figma의 밝은 시안 계열로 재구축한다. 이 PR 하나를 전체 서비스 디자인 완료라고 표현하지 않는다.

## 반드시 구현

- Pretendard Variable v1.3.9와 Inter Variable v4.1을 공식 원본·라이선스와 함께 로컬 자산으로 보관하고 실제로 로드한다. CSS @font-face 또는 next/font/local로 굵기별(400/600/700/800) 사용이 실제 파일에 연결되게 한다. 한글은 Pretendard, 라틴·숫자는 Inter를 사용한다. 런타임 외부 CDN과 새 패키지는 추가하지 않는다.
- 승인된 디자인 분석 브랜치의 brand-proposal.svg를 폰트 독립 흉흉 로고로 적용한다. 홈 링크의 이미지 alt는 흉흉이며 접근 가능한 홈 링크와 검색 링크를 제공한다. viewBox 0 0 128 48, 헤더에서 64×24px로 사용한다. 이 변경은 사용자 지시의 창작 로고 예외다.
- 검색 헤더는 18:2360/11:2135 기반 높이 52px, 좌우16px, radius16px, 흰색88%, blur20px, 0 8px 24px black7% 그림자, 14px 세로 구분선과 32px 검색 액션을 사용한다. 지원하는 기능에 맞춰 검색 안내는 '기사 키워드 검색…'으로 정한다. 주소 검색을 지원한다고 쓰지 않는다.
- 하단 메뉴는 18:2428/11:2210을 바탕으로 높이68px·radius28px·좌우16px 외곽 여백, 중앙54px 원형 제보 액션과 📢, 지도 아이콘 및 ≡ 목록 아이콘, 10px 라벨로 구성한다. 지도/검색에는 원본22px map-pin SVG, 목록에서는 Figma의 🗺 텍스트 아이콘을 사용한다. 첫 링크 라벨은 서비스의 이동 목적지에 맞춰 '지도'로 통일한다. 지도·목록의 aria-current=page, 검색의 지도 영역은 aria-current=location으로 설정한다. 메뉴 링크는 /, /report, /incidents 순서이며 제보 링크는 aria-label=제보하기다. 선택 색 #e8192c, 미선택 #94a3b8로 실제 경로와 일치시킨다. Figma 일부 시안의 목록 화면에 지도 탭이 활성인 표시는 그대로 복제하지 않는다.
- 공통 UI는 별도 컴포넌트 폴더로 분리한다: 브랜드, 검색 헤더, 하단 메뉴, 기사 필터 표면. AppShell은 화면별 조합과 FeatureErrorBoundary만 맡는다. 각 컴포넌트 폴더 안에 UI를 두고 필요할 때만 테스트를 함께 둔다. Figma 출력의 절대 배치를 통째로 복사하지 않는다.
- 지도는 전체 viewport를 지도 캔버스로 사용하고 헤더·필터·메뉴를 위에 띄운다. 현재 canvas에서 메뉴 높이를 빼서 생기는 하단 공백을 없앤다. 기사 마커·선택 시트·기본 중심·탭 뷰포트 복원·SDK 인증/오류·명시적 위치 권한 요청은 유지한다. 기존 기사 위치 안내가 새 필터와 겹치지 않게 배치한다. 기사 원·가로 기사 카드 본문은 후속 지도 PR이다.
- 목록은 공통 헤더와 필터 뒤에 본문을 둔다. 본문 카드 양옆 여백이 중복되지 않게 한 번만 적용한다. 별도 큰 '사건 목록' 제목은 시각적으로 숨기되 접근성 제목은 유지한다. 목록 데이터·더 보기·페이지별 재시도는 유지한다.
- 검색은 기존 전용 검색 행을 사용하므로 공통 검색 헤더·필터를 추가하지 않는다. 공통 하단 메뉴는 제공한다. 최근 검색 저장·삭제·추천 검색·결과·더 보기/재시도는 유지한다.
- /incidents/{id}와 /report에는 공통 헤더와 주 메뉴를 표시하지 않는다. 전용 헤더는 해당 라우트의 콘텐츠가 소유한다. 바깥의 떠 있는 카드 여백과 모서리를 제거해 흰 전체 화면으로 구성한다. 기사 상세는 기존 API/이미지/공유 동작을 유지하며 전용 헤더·본문의 외곽 구조만 조정한다. 제보는 기존 입력·첨부·오류 경계·재시도 키·60초 제한을 유지한다. 함수 로직이나 테스트를 수정해 UI와 무관한 리팩터링을 하지 않는다.
- 지도·목록 필터는 디자인대로 기간/카테고리/상태 칩 표면을 제공한다. 이 첫 단계에서는 모두 disabled이며 title에 '준비 중'을 포함한다. 기존 기사 API가 실제 필터를 지원하는 것처럼 URL 변경이나 가짜 필터 결과를 만들지 않는다. 지도에만 18:2368의 원본18px 필터 아이콘도 비활성으로 제공한다. 필터 행은 gap6px·radius20px·흰색88%·blur8px·실선 테두리로 구현하고 목록28px, 지도32px 높이를 기준으로 맞춘다.
- 기본 배경은 밝은 시안의 #f8fafc, 본문 #0f172a, 보조 #64748b, border #e2e8f0, 카드14px, 강조 #e8192c를 사용한다. 기존 Tailwind와 Preflight 미사용을 유지하고 필요한 기본 margin·line-height·border를 명시한다.

## 화면 및 자산 기준

Figma 파일 TCSILMzViAVqeHRphoyHCH. 지도18:2348, 선택45:3317, 검색11:1797/11:1864, 목록11:2123, 상세11:2043, 제보11:2221, 선택 시트19:2865, 공유34:3311을 전체 비교 대상으로 고정한다. 이번 구현에는 각 화면의 공통 기반만 적용하며 본문·신규 동작의 남은 차이는 기록한다. 링크45:3421은 최종 화면 지정이 아니다.

Figma 원본 SVG는 자산 URL의 원본을 다운로드하여 public에 보관한다. 지도 타일·휴대폰 외곽·iOS 시간/배터리/홈 인디케이터는 구현 자산으로 사용하지 않는다. 비교 때 시안의 iOS 상단37px·하단 홈 바 등 기기 영역을 분리하여 웹의 safe-area와 정렬한다. 웹에서 가짜 상태 표시줄을 넣지 않는다. 지도 헤더의 웹 상단 기준8px, 목록12px, 검색20px에 safe-area-inset-top을 더한다. 하단 메뉴는 웹 콘텐츠 하단8px + safe-area-inset-bottom을 기본으로 둔다. 393px에서 너비361px, 더 넓은 화면은 기존 max640px 안에서 확장한다.

원본 아이콘과 로고·폰트의 출처/라이선스/파일/치수를 문서에 기록한다. 로고·문구·메뉴 활성 상태의 명시된 예외 외 다른 시안 속성을 임의로 섞지 않는다. 스크린샷 자체를 앱 배경 또는 정적 화면 구현으로 쓰지 않는다.

## 제외 및 보호

기사 상태·분류·발생시각·타임라인·인용 수·거리·LIVE 통계를 임의 생성하지 않는다. 새 API나 보고 접수 저장 테스트를 운영에 실행하지 않는다. 지도 region 집계와 원 크기는 후속 지도 구현 항목이다. 기존 테스트·fixture·mock·테스트 명령, API 요청/timeout·포맷·상세 공유 및 첨부 흐름을 유지한다. 기존 승인 계획이나 sobaya 런타임을 수정하지 않는다.

## 완료 검증

1. 정확한 네 신규 행동 테스트 RED를 probe로 확인하고 사용자 승인 후 소바야 구현·전체 suite·gate·독립 review를 완료한다.
2. 기본 Next build 및 typecheck, format:check, lint와 전체 vitest가 통과한다.
3. 로컬 빌드를 실제 Naver SDK와 실제 API 읽기 전용 연결로 띄워 지도/검색/결과/목록/상세/제보를 촬영한다. 직접 진입·왕복 이동·이미지 없음·긴 제목·빈 결과·오류·시트를 확인한다. 제보 저장은 하지 않는다.
4. 393px 화면에서 헤더52px, nav68px, report 액션54px, 좌우16px, 로고64×24px 및 아이콘 원본 크기를 실측하고 Inter/Pretendard가 네트워크 로컬 파일 및 FontFaceSet에서 로드됨을 확인한다. 320px/393×852/667×375/1440×900에서 가로 overflow와 닫기·메뉴 가림을 확인한다.
5. 모든 화면을 Figma와 비교한 표에 이번 단계에서 일치시킨 항목과 후속 본문 차이를 구체적으로 남긴다. 공통 기반만 구현한 상태를 전체 디자인 완료라고 보고하지 않는다.
6. 저널·claim·검사·push와 dev 대상 리뷰 가능한 PR까지 진행한다. GitHub 리뷰 코멘트나 다른 사람 태그는 게시 전 사용자 허락을 받는다.

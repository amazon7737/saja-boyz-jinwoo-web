# 기사 목록 더 보기 — 명세 초안

2026-10-11 · 기준 dev e1ef3ca(PR #11 포함) · 사용자 검토 전 초안.

## 목적과 범위

`/incidents`에서 첫 20개 이후의 저장된 기사를 이어서 읽는다. 기존 제목·요약·발행 시각·출처·이미지 대체·상세 링크, 첫 페이지 오류/빈 결과/로딩은 그대로 유지한다. 검색·지도·필터·제보·서버 API·의존성은 변경하지 않는다.

## 동작

1. 첫 요청은 기존대로 `GET /news?offset=0&limit=20`이며 keyword를 보내지 않는다. PR #11의 `fetchArticleList`와 원본 total을 재사용한다.
2. 받은 원본 행이 1개 이상이고 아직 total에 도달하지 않았으면 목록 아래에 `더 보기` 버튼을 표시한다. 버튼을 눌러야 다음 페이지를 요청한다.
3. 다음 offset은 **성공한 응답들의 원본 items.length 누적값**이다. 중복 제거된 카드 수를 사용하지 않는다. 같은 article_id는 먼저 표시한 기사를 유지하며 입력 순서대로 한 번만 보여 준다.
4. 중복만 있는 페이지나 20개보다 짧은 페이지도 원본 행 수만큼 전진한다. 최신 응답의 total에 도달하거나 빈 다음 페이지를 받으면 더 보기를 종료한다. total은 고유 기사 수로 표시하지 않는다.
5. 추가 요청 중 기존 카드를 유지하고, `추가 기사를 불러오는 중이에요`를 role=status/aria-busy=true로 알린다. 버튼을 비활성화하고 빠른 연속 클릭도 추가 요청 한 건으로 제한한다.
6. HTTP 오류·네트워크 오류·잘못된 JSON·잘못된 응답 스키마면 기존 카드와 offset을 유지한다. `추가 기사를 불러오지 못했어요`와 `다시 시도`를 표시한다. 재시도는 실패한 같은 offset을 요청한다. 성공하면 오류를 지우고 이어 붙인다. 서버 오류 본문과 내부 예외 메시지는 화면에 노출하지 않는다.
7. 추가된 카드도 기존 ArticleCard의 상세 링크·원문·이미지 표시를 재사용한다. 원본 API 요청은 Next 서버에서 수행하며 브라우저에서 수집이나 이미지 생성 요청을 보내지 않는다.

## 검증

- 기존 58개 테스트·헤더·fixture·검증 명령을 유지하고 아래 새 행동 테스트 3개를 추가한다.
- 각 승인 항목은 pinned Sobaya 83af28d의 RED → 구현 → 전체 suite/hygiene checkpoint로 진행한다. 마지막 gate 및 독립 리뷰도 필요하다.
- 타입 검사·빌드 후 실제 Chrome에서 첫 페이지 → 더 보기 → 실패/재시도 → 추가 기사 상세 → 뒤로가기를 확인한다. 320/393/1280px의 버튼과 카드 배치를 확인한다.
- 브라우저 검증에는 제어 가능한 로컬 API fixture를 사용한다. 운영 수집이나 유료 이미지 생성을 호출하지 않는다. 단위 테스트의 jsdom은 Next 서버 액션 직렬화나 실제 브라우저 라우팅을 증명하지 않는다.

# 기사 이미지 로딩 실패 대체 표시 — 명세 제안

상태: 2026-10-05 작성, 정확한 명세·테스트·지원 입력은 아직 승인 전이다.
선행 코드: PR #3 / codex/article-list-api@7a2672a.
사용자가 이미지 404 등 로딩 실패 처리의 후속 작업 진행을 요청했다. 기존 8개 API 테스트와 13개 테스트, 기사 표시 정책의 승인은 유지한다.

## 목적과 동작

- API 메타데이터가 ready여도 브라우저에서 이미지 로딩이 실패하면 해당 카드의 깨진 img와 ‘AI 생성 이미지’ 캡션을 제거하고 기존 80×80 ‘이미지 없음’ 표시로 바꾼다. 404뿐 아니라 브라우저가 error로 알리는 네트워크·이미지 해독 실패에도 같은 동작을 적용한다.
- 제목·요약·기사 발행 시각·원문 링크·카드 개수와 순서를 유지한다. 다른 카드의 정상 이미지와 disabled placeholder에 영향을 주지 않는다.
- 정상 이미지의 alt=""(옆 제목과 중복되는 장식 이미지), 80×80 크기, AI 캡션 정책은 유지한다. 실패 상태는 기존에 읽을 수 있는 ‘이미지 없음’ 텍스트를 사용하며 새 중복 live announcement를 추가하지 않는다.
- 같은 React 화면과 article_id에 새 유효 이미지 URL이 들어오면 다시 이미지 표시를 시도한다. 새 URL 역시 실패하면 다시 placeholder로 바뀐다. 테스트에서는 apiOrigin 변경으로 이 경계를 확인한다. 이미지 수동 재시도 버튼이나 백그라운드 반복 요청은 추가하지 않는다.

## 범위와 보존

- 예상 구현은 기사 이미지 영역만 작은 client 경계로 분리하고 서버의 기사 조회·텍스트·시간·URL 검증을 그대로 두는 최소 변경이다. 구체 파일 분할은 승인된 동작을 만족하는 구현 선택이다.
- 기존 ArticleList의 items/apiOrigin 공개 입력과 모든 이전 승인 테스트·공용 UI·타입·목록 API 계약을 보존한다. 새로운 class 이름이나 내부 state 모양을 승인 테스트에 고정하지 않는다.
- 공용 글꼴·배지·카드 전체 높이, 더 보기·검색·필터·상세·제보·배포는 이번 구현 범위가 아니다.

## 수용 증거

- 새 파일 src/features/article-list/article-image-error.test.ts에 실제 React DOM과 Next/Image를 쓰는 행동 테스트 2개를 추가하는 안이다. React state, Next/Image, ArticleList를 mock하지 않는다.
- jsdom은 네트워크 이미지 다운로드와 실제 레이아웃을 구현하지 않는다. 테스트는 실제 DOM img의 error 이벤트를 주입해 상태 전환을 검증한다. HTTP 404/손상 이미지, 표시 80×80, 모바일 가로 넘침은 구현 후 실제 브라우저와 별도 로컬 이미지 fixture로 확인한다.
- 새 DOM 테스트만 파일별 jsdom 환경을 사용한다. 기존 Vitest 기본 node 환경·include·별칭·명령과 기존 21개 테스트는 변경하지 않는다.
- 기존 Node >=24 <25 범위와 pnpm10.34.6을 유지하기 위해 jsdom27.4.0 개발 의존성을 정확 버전으로 제안한다. package/lock 변경 전체는 support.patch 및 support.proposal.md를 검토한다.
- 승인 뒤 전체 23개 테스트·format·lint·typecheck·build·최종 gate와 독립 완료 리뷰를 수행한다. 지금의 RED 재현은 구현 완료나 승인 기록이 아니다.

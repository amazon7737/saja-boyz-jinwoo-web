# 검색 수집과 공유 확인

운영 주소는 https://hyunghyung.vercel.app 이며 브랜드는 흉흉 · 내 주변의 사건 사고입니다. 검색 노출 순위나 AI 답변의 인용을 보장하지 않습니다.

## Search Console 등록

1. 운영 배포를 완료한 뒤 사용자가 Google Search Console에서 URL 접두어 속성으로 운영 주소를 등록합니다.
2. HTML 태그 방식의 소유권 확인을 선택합니다. 사용자 제공 확인 태그는 공통 Next 메타데이터에 한 번만 설정되어 있습니다. 로컬 구현만으로 소유권이 확인되지 않으며 실제 운영 배포 후 확인을 실행해야 합니다.
3. 사이트맵 메뉴에 https://hyunghyung.vercel.app/sitemap.xml 을 제출합니다.
4. URL 검사에서 홈, 목록, 소개, 아카이브, 실제 기사 상세의 라이브 URL을 확인하고 필요한 공개 URL의 색인 생성을 요청합니다. 검색과 제보 화면은 noindex가 의도된 상태입니다.

등록·소유권 확인·제출은 사용자가 관리합니다. 확인 코드 자체는 이 문서에 복제하지 않습니다.

## 배포 후 확인

- robots.txt가 공개 경로와 정적 자원의 수집을 허용하고 운영 사이트맵을 가리키는지 확인합니다.
- 사이트맵의 네 정적 경로와 실제 최근 기사 링크가 운영 주소인지 확인합니다. API 장애 때는 정적 경로만 남아야 합니다.
- 일반 요청의 기사 상세는 메타데이터와 본문이 요청 단위로 동일한 조회 결과를 사용하고 API를 한 번만 호출하는지 확인합니다.
- facebookexternalhit, Twitterbot, kakaotalk-scrap 사용자 에이전트로 실제 상세 URL의 원시 HTML head에 제목, 요약, 대표 URL, 공통 PNG가 있는지 확인합니다. 브라우저 DOM 확인만으로 대체하지 않습니다.
- 원시 홈 head의 소유권 확인 태그가 정확히 한 번 있는지, 공통 PNG가 정상 응답하는지 확인합니다.
- SDK 미설정 상태와 모바일 화면에서 지도 아래의 서비스 안내와 기사 목록 링크가 읽히고 눌리는지 확인합니다. 지도 높이와 기존 오버레이도 확인합니다.
- 아카이브 이전/다음 링크, 빈 페이지와 장애의 noindex, 상세의 기사 없음 안내·목록 복귀 링크와 장애 복구를 확인합니다. 존재하지 않는 전역 경로는 HTTP 404인지 확인합니다. 색인 보고서 반영에는 시간이 걸릴 수 있습니다.

Next의 `notFound()`는 스트리밍이 시작된 응답에서는 HTTP 200과 noindex를 반환하고, 스트리밍 전에는 HTTP 404를 반환합니다. 기존 로딩 경계를 유지하므로 없는 기사도 HTTP 200일 수 있습니다. 상세 검증에서는 관측된 상태 코드를 기록하고 기사 전용 없음 안내, noindex, 허위 기사 JSON-LD·canonical 부재를 함께 확인합니다. HTTP 404를 강제하는 구조 변경은 적용하지 않았습니다.

## 수집 범위와 한계

사이트맵은 기존 기사 API의 첫 20개 원시 행을 최대 한 번, 5초 제한으로 조회하고 ID 중복을 제거합니다. 전체 과거 기사 목록이 아니며 근거 없는 수정 시각을 넣지 않습니다. 요청은 no-store이고 장애 시 네 정적 URL로 돌아갑니다.

아카이브는 20개 원시 행 단위 offset 페이지입니다. 중복을 화면에서 제거하면 카드 수가 20개보다 적을 수 있고 total은 고유 사건 수가 아닙니다. 새 기사 수집 중에는 페이지 사이의 위치가 달라져 중복 또는 누락이 발생할 수 있으므로 안정된 스냅샷이라고 보장하지 않습니다.

안정 커서, 지역·분류별 공개 페이지, 전체 사이트맵용 API는 서버 후속 과제입니다. 현재 없는 API나 분류·진행 상태 정보를 가정하지 않습니다.

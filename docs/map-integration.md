# 네이버 지도 연결

홈(`/`)은 네이버 Maps Dynamic Map을 실제 배경 지도로 사용한다. 기본 중심은 서울시청(37.5665, 126.9780), zoom 12다. 기본 중심을 사용자나 사건 위치로 해석하지 않는다.

## 실행 설정

1. `.env.example`을 참고해 ignored `.env.local`에 `NEXT_PUBLIC_NAVER_MAP_CLIENT_ID`를 설정한다. 웹 SDK는 Client Secret을 사용하지 않는다.
2. 네이버 콘솔에서 Dynamic Map을 활성화하고 Web 서비스 URL에 개발 주소 `http://localhost:3000`과 실제 배포 주소를 등록한다.
3. 개발 서버는 `pnpm dev`로 실행한다. 공개 환경변수는 빌드 때 포함되므로 배포 설정을 바꿨다면 다시 빌드한다. 키가 없는 빌드는 지도 대신 관리자 문의 안내를 표시한다.

SDK 주소는 `https://oapi.map.naver.com/openapi/v3/maps.js`이며 쿼리 키는 `ncpKeyId`다. 레거시 `ncpClientId`를 사용하지 않는다. 실제 자격 값은 저장소나 문서에 기록하지 않는다.

## 구현과 동작

- `src/features/map/ui/map-home/`에 지도 컴포넌트·설정 안내·관련 테스트를 모았다. SDK 연결은 이 기능 안에 있으며 제품 의존성이나 전역 store를 추가하지 않았다.
- 홈에서만 AppShell 헤더를 지도 위에 배치한다. 기존 사건 검색(`/search`), 목록, 제보 메뉴와 오류 경계는 유지한다.
- SDK 스크립트를 재사용하며 실패한 스크립트는 재시도 때 교체한다. 로딩·스크립트 실패·10초 시간 초과·인증 실패를 표시하고 재시도를 제공한다. 크기 변경 시 지도를 갱신하며 언마운트 때 지도·위치 표시·타이머·리스너·관찰자를 정리한다.
- 내 위치는 클릭할 때만 요청한다. 처리 중 중복 요청을 막고 성공 시 중심을 이동하며 Figma 위치 표시를 하나만 유지한다. 권한 거부·시간 초과·미지원 안내 후에도 기본 지도는 유지한다. 늦은 응답은 무시하며 위치 응답·마커·정확도를 저장하거나 서버에 보내지 않는다. 재진입 복원을 위해 마지막 지도 중심·확대 수준만 탭 메모리에 유지한다.
- 네이버 로고와 출처를 가리지 않도록 하단 메뉴 공간을 확보했다. 지도 이미지로 실제 SDK를 대체하지 않는다.

Figma 근거: [지도 기본 18:2348](https://www.figma.com/design/TCSILMzViAVqeHRphoyHCH?node-id=18-2348), [선택 필터 45:3317](https://www.figma.com/design/TCSILMzViAVqeHRphoyHCH?node-id=45-3317). 위치 아이콘은 해당 Figma 원본 SVG를 사용한다. iOS 상태바와 지도 배경 이미지는 제품 자산에 포함하지 않는다.

## 실제 기사 좌표 연결

홈 서버 컴포넌트가 `/map/articles` 전체 페이지를 조회하고 `resolved` 위치만 마커에 전달한다. 좌표가 같은 기사들은 숫자 마커로 묶고, 하단 선택 패널에서 모든 기사를 확인해 기존 상세로 이동한다. `region`·`neighborhood`는 **지역 대표 위치 · 실제 발생 지점과 다를 수 있습니다**라고 표시한다. 지도 시작 위치를 자동 변경하지 않으며 **기사 위치 보기**를 눌러 전체 기사 범위를 확인한다. 고유 위치가 하나면 중심과 확대 15로 이동하고, 여러 곳이면 fitBounds로 범위를 맞춘다. SDK는 길이가 1인 좌표 배열의 fitBounds를 처리하지 않는다.

API 실패·좌표 없음 상태에서도 지도와 내 위치는 유지한다. 상태/좌표/원문 근거와 정확도에 관한 검증, 페이지 이동 한계, 서버 처리와의 책임 구분은 [지도 기사 API 소비 계약](map-api-contract.md)을 따른다. 이미지 대체 표시·기사 텍스트/발행일 처리·상세 경로는 기존 구현을 재사용한다.

## 피그마 마커와 하단 선택 패널

2026-10-14 사용자 요청으로 [지도 18:2348](https://www.figma.com/design/TCSILMzViAVqeHRphoyHCH?node-id=18-2348)과 [하단 패널 19:2990](https://www.figma.com/design/TCSILMzViAVqeHRphoyHCH?node-id=19-2990)의 디자인 컨텍스트·스크린샷을 다시 확인했다. 일반 마커 18:2385, 선택 링 18:2378, 닫기 19:3143의 원본 SVG를 `public/map/`에서 제공한다. 단일 마커는 24px 슬롯에 24px 일반/28px 선택 SVG를 중심 정렬한다. 같은 좌표 묶음은 빨간 반투명 원형이며 2–5건 38.4px, 6–9건 48px, 10건 이상 72px다. 색으로 실제 사건 상태를 주장하지 않는다.

선택 패널은 화면 하단 전체 폭(최대 640px)에 표시하고 선택 중 하단 메뉴를 덮는다. 긴 기사·같은 위치의 여러 기사는 내부 스크롤로 읽을 수 있다. 24px 상단 모서리, 16px 간격, 18px 제목, 80px 실제 API 이미지, 13px 요약을 따른다. 이미지가 준비되지 않으면 기존 대체 표시를 사용한다. 피그마 예시의 사건 상태·주변 거리·발생 시각은 API 계약에 없어 생성하지 않으며, `pubDate`는 **기사 발행**으로 표시한다.

마커는 이름 있는 버튼이고 Enter/Space로 선택할 수 있다. 선택 시 닫기 버튼에 포커스를 옮기며, 닫기/Escape 후 원래 마커에 스크롤 없는 포커스를 복원한다. 패널의 핸들은 시각 표현이며 드래그 제스처는 이번 범위에 없다. 기존 헤더·필터·메뉴 디자인 전체 개편도 포함하지 않는다.

## 후속 API 범위

실제 사건 단위 병합, 줌 클러스터·분류/기간/상태 필터·핫한 사건은 추가 서버 계약이 필요하다. 현재 마커는 기사 단위이며 `pubDate`를 사건 발생 시각으로 바꾸거나 상태를 추측하지 않는다.

2026-10-10 실제 Chrome에서 localhost SDK·인증·지도 타일 HTTP 200, 내 위치 이동, 오류 재시도, 320/393/1280px 화면과 검색 왕복 후 스크립트 1개를 확인했다. 배포 도메인의 등록 여부·인증과 콘솔 요금/한도는 별도 확인이 필요하다.

공급자 근거: [SDK 시작 가이드](https://navermaps.github.io/maps.js.ncp/docs/tutorial-2-Getting-Started.html), [Client ID 및 서비스 설정](https://navermaps.github.io/maps.js.ncp/docs/tutorial-1-Getting-Client-ID.html).

## 화면 이동 후 지도 복원

같은 탭에서 지도에서 목록·상세·검색으로 이동한 뒤 돌아오면 마지막 중심과 확대 수준을 복원한다. 내 위치 버튼으로 이동한 중심도 지도 상태로 유지되며, 복귀할 때 위치 권한을 다시 요청하지 않는다. 새로고침·새 탭에서는 기본 서울 중심·확대 12로 시작한다.

상태는 마지막 clientId의 한 건만 모듈 메모리에 보관한다. localStorage·sessionStorage·쿠키·서버 저장을 사용하지 않는다. SDK 중심·확대 값을 읽지 못하거나 유효하지 않으면 이전 유효 상태를 유지하고 지도 정리를 계속한다. clientId 변경은 기본 상태로 초기화한다.

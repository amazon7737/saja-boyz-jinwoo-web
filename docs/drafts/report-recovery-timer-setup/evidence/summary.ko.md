# 임시 사본의 테스트 셋업 교정 후보 검증

제품 소스는 `b23c5323c5e622d48289afc0a5657f787c356652` 그대로이며, 승인된 6개 테스트 본문과 기존 테스트를 수정하지 않았다. 후보 변경은 초기 `root.render`의 `act` 직후 `await advance(1);` 한 줄뿐이다. 원본 체크아웃에는 적용하지 않았다.

- 기존 헤더 + 승인 본문 6개: 5 PASS / 1 FAIL, 종료 1. `reportFailureCleanup`의 타이머 수만 0 대신 1이었다.
- 교정 후보: 6 PASS, 종료 0.
- 전체 회귀: 19개 파일 / 81개 테스트 PASS, 106.58초, 종료 0. 기존 로컬 HTTP/Chrome 테스트 실행 권한을 사용했다.
- 타입 검사, ESLint, Prettier: 모두 종료 0.
- 전체 소스 대조: 테스트 조합 파일 외 `src`의 58개 파일이 기준 커밋과 바이트 동일하다. 제품 page 파일은 원본 체크아웃과 사본 모두 기준 커밋과 동일하다.

독립 진단은 요청 전 fetch 호출이 0인 상태에서 1ms 타이머 1개를 관찰했다. 스택은 Next Link의 `use-intersection` → `requestIdleCallback` 폴백 → `setTimeout(1)`로 이어진다. 초기 렌더 뒤 1ms를 진행하면 요청 없이 타이머가 0이 된다. 따라서 이 후보는 요청 전에 Next 초기화만 완료하며, 60초 요청 제한이나 그 검증을 건너뛰지 않는다.

이 결과는 후보의 검증이며 승인 또는 하네스 완료가 아니다. 실제 공통 헤더 교체는 정확한 변경 내용에 대한 인간의 승인 후 별도로 진행해야 한다. 최초 실행 한 번의 cwd 실수는 즉시 보고했고, 보관된 before.txt는 이후 올바른 임시 사본에서 실행한 6개 결과다.

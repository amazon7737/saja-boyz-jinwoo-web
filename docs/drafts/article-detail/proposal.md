# 기사 상세·진입·공유 구현안

2026-10-10 · `codex/article-detail` · 대상 PR: `dev`

사용자 요청에 따라 기사 상세 화면, 목록·검색에서 상세 진입, 상세 URL 공유를 구현한다. 제품 구현과 PR 생성은 요청받았으며, 아래 신규 테스트 및 기존 테스트의 기대 변경은 검토 전 초안이다.

## 제공할 동작

1. `/incidents/{article_id}`를 직접 열면 서버에서 `GET /news/{article_id}`를 한 번 조회한다. 목록을 다시 훑지 않는다. 요청마다 최신 데이터를 읽고 5초 제한을 둔다.
2. 제목, `description` 요약, 기사 발행 시각, 원문 링크, 준비된 AI 이미지를 표시한다. 요약을 기사 전문으로 부르지 않는다. 이미지에는 `AI 생성 이미지` 표시를 유지한다.
3. 제목의 태그·엔티티, 원문 URL, 이미지 URL은 기존 목록과 동일한 안전 규칙으로 처리한다. 준비되지 않았거나 로딩이 실패한 이미지는 대체 표시한다.
4. 잘못된 ID와 API 404는 기사 없음으로 처리한다. 설정·통신·타임아웃·비정상 응답은 다시 시도할 수 있는 오류로 구분한다. 내부 오류 내용을 화면에 노출하지 않는다.
5. 목록과 검색 결과의 기사 제목을 누르면 같은 상세 URL로 이동한다. 원문 링크는 별도로 유지한다. 검색 키워드 전달과 중복 제거를 보존한다.
6. 공유 버튼은 웹앱의 `/incidents/{article_id}` URL을 사용한다. 지원 브라우저는 기본 공유창을 열고, 미지원 또는 취소 이외의 공유 오류는 링크 복사로 이어진다. 사용자가 공유를 취소하면 복사하지 않는다. 복사도 불가능하면 직접 복사할 URL을 제공한다. 복사 완료 안내는 실제 성공 후에만 표시한다.
7. 상세의 목록 이동은 `/incidents`, 닫기는 지도 홈 `/`으로 연결한다. 브라우저 뒤로가기를 사용하면 이전 검색 URL로 돌아갈 수 있다.

## 디자인 적용

[Figma 상세 11:2043](https://www.figma.com/design/TCSILMzViAVqeHRphoyHCH?node-id=11-2043)의 흰 배경, 상세 헤더, 제목, 큰 이미지, 출처·요약, 빨강 테두리 공유 버튼을 기존 토큰으로 구현한다. 393px과 데스크톱에서 확인한다.

현재 API에 없는 카테고리·사건 상태·위치·타임라인·인용 횟수는 만들지 않는다. 웹앱에 휴대폰 상태바를 그리지 않는다. [공유 시안 34:3311](https://www.figma.com/design/TCSILMzViAVqeHRphoyHCH?node-id=34-3311)의 미확정 SNS별 선택 UI 대신 브라우저 기본 공유/복사를 사용한다.

## 서버 연결 근거

- Go 서버 `527532ca528ddf53b61e610ef4de1bc303f42275`의 단건 조회 API가 OCI에 배포됐다.
- API 기준 주소: `https://poem-news.168.107.37.12.sslip.io`.
- 정상 응답은 기존 목록 항목과 같은 `collection_id`, `article_id`, `article`, `image_status`, `image_url`이다. 이미지 준비 시 `/images/{article_id}.jpg`를 제공한다.
- 기존 비공개 환경변수 `NEWS_API_BASE_URL`을 그대로 사용한다. 브라우저에 네이버·Cloudflare 키를 전달하지 않는다.

## 기존 테스트와 충돌하는 부분

현재 테스트는 상세 화면이 없던 단계의 조건을 포함한다. 아래 네 테스트의 **제안된 정확한 본문**을 `replacement-tests.md`와 `review.ko.md`에 제시한다. 실제 테스트 파일은 아직 수정하지 않는다.

| 테스트                               | 변경 이유                                                                          | 유지하는 검증                                                   |
| ------------------------------------ | ---------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `articleCardsIdentityAndPublication` | 상세 링크 금지 조건을 제거하고, 링크 존재 검증은 신규 진입 테스트로 이동                    | 중복 제거, 제목·요약, 원문, 발행 시각, 가짜 사건 정보 금지      |

## 구현 순서와 확인 범위

`failed-test.draft.md`의 순서대로 단건 조회·오류·안전한 표시·타임아웃·이미지 오류·공유·목록/검색 진입·로딩/404를 구현한다. 실행 테스트는 API를 가짜 응답으로 대체하므로 실제 OCI 접근, 실제 운영 데이터 품질, OS 공유창의 외형을 보증하지 않는다. 완료 전 실제 API 읽기와 브라우저 직접 URL 진입·새로고침·검색 결과 진입·좁은 화면·공유/복사도 별도로 확인한다.

기존 전체 테스트, 포맷, lint, 타입 검사, 빌드와 Sobaya gate·독립 리뷰를 통과한 뒤 작업 기록을 정리하고 `dev` 대상 PR을 연다. 지도·최근 검색어·제보 기능과 공용 토큰·의존성은 이번 범위에 포함하지 않는다.

## 검토 후 필요한 승인 범위

- 이 동작 명세와 `review.ko.md`가 보여 주는 신규 실행 테스트·공통 헤더.
- 위 네 기존 테스트의 정확한 대체 본문. 다른 기존 테스트·헬퍼·픽스처는 유지한다.
- 승인된 이 명세를 새 기능의 `spec.md`로 등록하고 테스트 계획을 `failed-test.md`로 등록하는 것. 현재 `spec.md`는 만들거나 수정하지 않았다.

승인 뒤 구현·검증·PR 생성은 이미 요청받은 범위대로 이어간다.

실행 환경은 Node 24.19.0, pnpm 10.34.6, 기존 lockfile의 node_modules다. [probe 로그](probes/)는 최종 원본 블록을 사용한 결과다. 1·2·3은 기존 입력 확인과 실제 접수 기대의 차이, 6·7·11은 fetch 0회, 8·9는 서버 오류 안내 부재, 10은 설정 오류 안내 부재로 실패한다.

현재 제품에 실제 접수 기능이 없음을 검증한 것이며, 뒤쪽 assertion까지 모두 실행되어 올바름이 입증된 것은 아니다. 구현이 여러 후속 항목을 함께 만족시키면 하네스가 ALREADY GREEN으로 기록한다. 기존 첨부 4·5는 새 미구현 계획에 추가하지 않고 교체 기준선에서 보존한다.

## 초안 리뷰 반영

- 길이 초과마다 요청 수가 그대로이고 정상 입력마다 정확히 한 번 늘어나는지 확인한다.
- 네트워크/서버 오류 후 다섯 필드와 첨부를 유지하고 제출 잠금이 풀리는지 확인한다.
- 잘못된 JSON 모양뿐 아니라 실제 HTML 응답 본문의 JSON 파싱 실패도 포함한다.
- 제목 변경과 첨부만 변경한 재시도 모두 새 요청 키를 쓰는지 확인한다.
- 한국시간 입력 해석은 TZ=UTC에서 확인하여 실행 컴퓨터의 시간대에 의존하지 않도록 한다.
- 주소 설정 사례마다 컴포넌트를 새로 mount하여 이전 빈 설정 상태가 검사를 가리지 않게 한다.

첫 초안의 test-11은 호출 횟수 확인 없이 존재하지 않는 첫 호출을 읽어 TypeError가 났다. 최종 초안은 먼저 호출 횟수를 확인하므로 현재 코드의 미전송을 명확한 assertion RED로 기록한다. 기존 승인 파일이나 하네스 판정 기준을 수정하지 않았다.

## 검증 한계와 구현 후 확인

- fetch는 고정 접수증/오류를 반환하는 mock이다. 실제 Go·Traefik·CORS·TLS·디스크 저장을 이 프런트 테스트가 검증하지 않는다.
- 파일 fixture의 size를 모사하며 내용은 한 글자다. 실제 파일 시그니처·전체 업로드 크기는 서버 테스트가 담당한다.
- 합성 FileList와 submit 이벤트를 사용한다. 네이티브 파일 선택·모바일 키보드·실제 Enter 제출·스크린 리더·업로드 도중 화면 이탈은 브라우저에서 별도 검증한다.
- Storage.setItem spy는 해당 API만 확인한다. 모든 저장소/네트워크 경로의 부재를 증명하지 않는다.
- 새로고침 후 재시도 키는 보존하지 않는다. 서버가 저장했지만 응답을 받기 전 페이지를 닫았다면 새 접수와의 중복은 이번 보장 범위 밖이다.
- 제품 코드 변경·승인 등록·구현 worker·최종 gate·신규 기능 빌드/브라우저 검증·운영 배포는 수행하지 않았다. 기존 전체 70개 테스트는 PR #15에서 검증된 기준이며 이번 문서 작업에서 전체 suite를 재실행했다고 주장하지 않는다.

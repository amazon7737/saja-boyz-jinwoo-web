# 실제 제보 접수 구현 전 검토안

2026-10-13 · 승인 전 · 사용자 선택: 익명 접수 + 첨부 저장

[접수 계약안](../../report-submission-contract.md)에 화면·API·저장·기본 제한을 정리했다. 이 문서는 해당 계약을 검증할 **정확한 테스트 입력과 기존 테스트 교체**를 제안한다. 지금 제품 코드·기존 테스트·승인 기록은 변경하지 않았다.

## 기존 기준선을 바꾸는 이유

PR #15(e045e01)는 실제 전송 없이 `입력 확인 완료`와 미전송 안내를 표시하도록 승인됐다. 따라서 그 기대를 유지한 채 실제 접수를 구현할 수 없다. 기능 플래그로 충돌을 숨기지 않고 다음 교체를 제안한다.

| 기존 테스트 | 제안 |
| --- | --- |
| `reportFormFields` | 입력·레이블·분류 검증 보존, CTA를 제보 접수로 변경하고 한국시간·비공개 안내 추가 |
| `reportRequiredFields` | 필수 오류·포커스 검증 보존, 올바른 입력은 실제 요청과 접수 응답 표시로 변경 |
| `reportTextLimits` | 기존 trim·길이 경계 보존, 성공은 서버 접수 후 표시하고 새 제보 작성으로 초기화 |
| `reportAttachments` | 실행 본문을 바이트 그대로 보존. 이미 통과하는 회귀 검사 |
| `reportAttachmentLimits` | 실행 본문을 바이트 그대로 보존. 이미 통과하는 회귀 검사 |
| `reportLocalConfirmation` | 로컬 미전송 기대를 multipart 요청·정상 응답·문자열 안전 표시 검증으로 교체 |

기존 6개를 최종 11개로 구성한다. 유지할 첨부 2개는 새 미구현 항목으로 세지 않는다. 새 동작 9개는 필드/필수/길이 3개, payload·중복 제출·동일 요청 재시도·실패 응답·주소 미설정·수정 후 재시도 6개다. 현재 70개인 전체 테스트는 모두 구현한 뒤 75개가 된다.

## 정확한 검토 파일

- [review.ko.md](review.ko.md): 공통 헤더와 11개 본문을 생략 없이 한국어 주석으로 설명한 검토본.
- [replacement-baseline.txt](replacement-baseline.txt): 승인 후 기존 `src/app/report/report-form.test.ts`를 교체할 초기 기준선. 새 공통 헤더와 기존 첨부 2개를 포함한다.
- [failed-test.draft.md](failed-test.draft.md): 위 기준선에 하네스가 한 항목씩 추가할 새로운 동작 9개.
- `header.txt`, `test-1.txt`~`test-11.txt`: 검토본·기준선·계획의 원본 블록. 4·5번은 보존 대상이다.
- [verification.md](verification.md): 실행 결과, 독립 검토, mock과 probe의 한계.

승인은 위 계약과 정확한 실행 입력, 그리고 **기존 로컬 확인 테스트 4개를 교체하는 기준선**에 대한 승인을 뜻한다. `spec.md`는 자동 편집하지 않고 별도 사용자 소유 명세로 다룬다. 본 초안을 명세로 채택할지도 함께 확인한다.

## 승인 후 순서

1. 승인한 계약을 명세로 채택하고 새 기준선을 등록한다. 기존 승인본은 이미 보관된 PR #15 계획과 Git 이력에 남긴다.
2. Go 서버의 접수·첨부·저장·중복 방지를 먼저 검증하고, 프런트 9개 항목을 한 번에 하나씩 하네스로 구현한다.
3. 전체 suite·타입·포맷·lint·빌드와 브라우저 실제 업로드를 확인하고, 독립 완료 리뷰 후 PR을 준비한다.
4. 운영 활성화는 서버 환경 변수·볼륨·웹앱 origin·Traefik 경로를 갖춘 결과를 검토하여 진행한다. 초안 probe는 실제 사용자 제보나 운영 파일을 만들지 않는다.

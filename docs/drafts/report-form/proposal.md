# 제보 입력 화면 1차 검토안

2026-10-13 · 기준 dev `b405d3a` · 승인 전 초안

## 남은 배정과 범위

`docs/work-split.md`의 사용자 승인 분담은 amazon에게 제보 폼·입력 검증·첨부·제출 상태를 배정한다. 현재 `/report`는 준비 안내뿐이다. 목록·상세·이미지 실패 대체·목록 페이지네이션은 PR #2/#3/#4/#10/#12로 병합됐다. 열린 PR #14의 지도 위치 복원은 easter721 영역이다.

실제 제보 API·첨부 저장·인증·검토 정책은 아직 없다. 사용자에게 **프런트 입력 화면 먼저**와 **Go 서버의 실제 접수까지** 중 범위를 질문한 상태다. 아래는 전자를 선택할 경우 바로 검토할 수 있는 제안이며, 확정된 요구사항이나 기존 승인이 아니다. 후자를 선택하면 서버 계약과 실제 제출 상태 테스트를 추가로 준비해야 한다.

## 1차 동작 제안

- `/report` 준비 안내를 카테고리, 발생 날짜 및 시간, 제목, 발생 위치, 상세 내용, 선택적 첨부 입력으로 바꾼다.
- `IncidentCategory`와 `categoryLabels`를 재사용한다. 사회·안보·정치·국제 외 분류를 임의로 추가하지 않는다. 제보 입력은 아직 사건이 아니므로 `Incident` 타입 전체를 사용하지 않는다.
- 다섯 텍스트/선택 필드를 필수로 하고 공백만 있는 입력을 거부한다. 오류는 필드 옆에 표시하고 `aria-invalid`/`aria-describedby`로 연결한다. 필수 오류는 `필수 항목이에요`, 길이 초과는 `100자를 초과했어요`처럼 한도를 포함한다. 첫 오류 필드로 포커스를 옮긴다.
- 제목 100자, 위치 200자, 내용 5,000자를 제안한다. 앞뒤 공백을 제거한 JavaScript 문자열 길이 기준이다. 발생 시각은 브라우저의 `datetime-local` 입력을 사용하며 기본 예시 날짜를 실제 값으로 채우지 않는다. 미래 시각 금지 등 추가 정책은 이번 초안에 넣지 않는다.
- 첨부는 선택 사항이다. JPEG·PNG·WebP 이미지와 MP4·WebM 동영상, 파일당 최대 10 MiB, 합계 최대 3개를 제안한다. SVG·기타 MIME·빈 파일·초과 용량은 거부한다. 한 번에 고른 묶음에 오류가 있으면 그 묶음을 추가하지 않고, 기존 선택은 유지한다. 파일명과 삭제 버튼을 보여주며 삭제 뒤 같은 파일을 다시 고를 수 있다.
- 서버가 없는 1차 범위에서는 버튼 이름을 **입력 확인**으로 한다. 유효하면 **입력 확인 완료**와 **입력한 내용은 전송되지 않았어요**를 보여주고 값을 유지한다. 접수 완료로 표현하거나 가짜 접수번호를 만들지 않는다.
- 네트워크 제출·브라우저 영구 저장·파일 업로드·자동 위치 조회는 하지 않는다. 파일 선택 검증은 브라우저 UX이며 향후 서버의 파일 검사나 보안 검증을 대신하지 않는다.

문자 수·파일 수·크기·형식·필수 항목·전송 전 단계 분리는 이번에 제안하는 결정이다. 이 값들은 기존 분담이나 Figma에서 승인된 정책이 아니다.

## 디자인과 실제 구조

Figma [제보 11:2221](https://www.figma.com/design/TCSILMzViAVqeHRphoyHCH?node-id=11-2221)의 디자인 컨텍스트와 393 × 852 렌더를 2026-10-13에 확인했다. 제목·닫기, 20px 필드 간격, 회색 입력 배경, 10px 입력 모서리, 120px 내용 영역, 점선 첨부 박스, 빨간 CTA가 기준이다. 기기 시각·통신·배터리는 브라우저 UI에 복제하지 않는 안이다.

현재 AppShell은 `/report`에서도 헤더와 하단 메뉴를 보여준다. `docs/ui-contract.md`의 숨김 설명은 문서 첫머리에서 재개발 목표로 정정된 내용이다. 이번 안은 공용 AppShell을 수정하지 않고 그 본문에 폼을 배치한다. Figma의 독립 전체화면/고정 하단 CTA와는 차이가 있으므로 승인 시 확인할 사항이다. 닫기는 지도 `/`로 연결하고 CTA는 본문 흐름에 둬 메뉴와 겹치지 않게 한다.

## 브라우저에서 별도로 확인할 것

- 393px 및 좁은 화면에서 입력·오류·첨부 목록·CTA가 하단 메뉴와 겹치거나 수평으로 넘치지 않는지 확인한다.
- 실제 버튼 클릭과 Enter 후 기본 폼 이동/추가 요청이 없고 URL·입력값이 유지되는지 확인한다. 합성 submit 테스트는 네이티브 동작을 실행하지 않는다.
- 실제 파일 선택창에서 선택 → 삭제 → 동일 파일 재선택이 되는지 확인한다. 단위 테스트는 파일 metadata와 change 이벤트를 직접 주입하므로 이 동작 전체를 입증하지 않는다.
- 키보드로 필드·삭제·확인·닫기에 접근할 수 있고, 첫 오류로 포커스가 옮겨지며, 오류와 미전송 안내를 읽을 수 있는지 확인한다.

# 조회수 상위 기사 검색 안내

메인·목록 검색 헤더와 검색 화면의 빈 입력창에 `기사 제목 검색하기`를 표시한다. 한국시간 오늘 조회수 상위3개 공개 사건 제목을 무작위 순서로 섞은 뒤5초마다 순환한다. 한 순환 안에서는 같은 제목을 반복하지 않는다. 제목이1개면 고정하고, 조회 기록이 없거나 API가 실패하면 기존 `기사 키워드 검색` 안내를 유지한다.

`SearchPromptProvider`는 앱 진입 시 순위를 한 번 받아 공유하므로 헤더·입력창이 각각 중복 요청하지 않는다. 순위 자체는 다음 앱 진입/새로고침 때 갱신하고, 롤링마다 API를 호출하지 않는다. 긴 제목은 기존 헤더의 말줄임 스타일을 따른다. 입력값과 검색 제출·검색 진입 링크는 변경하지 않는다. 스크린리더의 검색 이름도 고정하고 자동 안내 방송을 추가하지 않는다. 동작 줄이기 설정에서는 첫 제목을 고정하며 숨겨진 탭에서는 제목 전환을 건너뛴다. 해제 시 요청·타이머를 정리한다.

## API 경로

브라우저 → `GET /api/search-headlines` → `GET ${NEWS_API_BASE_URL}/news/popular/today` → 공개 사건의 오늘 고유 방문자 순위.

프런트 서버는 최대3개 양수 `views_today` 항목과 한국 날짜/시간대 계약을 검증한 후 HTML 강조와 엔티티를 일반 제목 텍스트로 정리해 `{titles: [...]}`만 브라우저로 반환한다. 호출은5초 제한과 `no-store`를 사용한다. 설정 누락·잘못된 응답·서버 오류는503과 빈 제목을 반환하고 상세 오류는 노출하지 않는다. 새로운 브라우저 공개 API 키는 필요하지 않다.

## 반영 순서

먼저 [poem-news PR #14](https://github.com/team-poem/poem-news/pull/14)를 머지·배포하고 운영 `/news/popular/today`를 확인한다. 현재 운영에는 조회수 추적의 선행 변경도 미배포여서 함께 확인해야 한다. 이후 이 프런트 PR을 적용한다. 기존 `NEWS_API_BASE_URL` 설정을 재사용한다. 실제 조회가 없는 초기에는 기본 안내가 정상이다.

이번 작업에서는 운영 배포·운영 조회수 생성은 실행하지 않았다. 로컬 브라우저 검증은 별도 임시 디렉토리의 합성 기사와 로컬 Go 서버만 사용했다. 확인한 범위는 조회 API→프런트 프록시→모바일 브라우저 제목 전환·사용자 입력값 보존이며 합성 검증 데이터는 운영 뉴스가 아니다.
